# 模块导入、宏与性能

VAS 的原生 `vasbuild` 和 `vasrun` 共用 `vas::ScriptBuilder` 预处理层。原有嵌入式 `CScriptBuilder` 保持独立；直接使用它的宿主需要切换到 VAS 包装层才能获得这里的模块和宏语义。

## 依赖语法

```cpp
import math;           // math.vas
import utils.math;     // utils/math.vas
#include "math.vas"
#include <math.vas>
```

模块导入必须位于文件作用域。上述形式最终都将依赖加入同一个编译单元，函数、类型、变量和宏的可见性一致，不自动建立命名空间。需要隔离符号时，在模块文件内显式声明 `namespace`。原来的函数绑定语法 `import int host(int) from "other";` 继续保留。

引用和去重规则：

| 写法 | 查找规则 |
| --- | --- |
| `import math;`、双/单引号 include | 先尝试引用文件所在目录；不存在时查找入口目录和配置的搜索目录 |
| `<math.vas>` | 查找入口目录和配置的搜索目录，不优先查找嵌套引用文件所在目录 |
| 绝对路径 include | 直接解析指定路径 |

默认搜索根包含编译入口目录。工具还读取 `VAS_INCLUDE_PATH`：Windows 用分号分隔，Linux/macOS 用冒号分隔；其中的相对目录基于入口目录。嵌入式宿主可使用 `AddSearchPath`，该 API 的相对路径基于进程工作目录。搜索根内有多个不同文件匹配时明确报歧义，不随机选一个；引号和 import 的本地匹配优先。

同一次构建按绝对路径、斜杠统一、词法 `.`/`..` 消解后的文件名去重，Windows 对 ASCII 路径字母忽略大小写。三种形式可交替引用、重复引用、循环引用，同一文件只处理一次。此规则不做物理符号链接身份识别。重新构建会清空宏、路径解析和文件去重缓存，重新读取输入，避免依赖修改后使用旧内容。

## 所有宏自动可见

```cpp
// math.vas
#define MATH_VERSION 1
#define MATH_ADD(a, b) ((a) + (b))

// main.vas
import math;
println("版本：{}，结果：{}", MATH_VERSION, MATH_ADD(50, 22));
```

宏字典由本次编译单元共享，按照源码顺序处理。导入方在引用前定义的宏对依赖文件可见；依赖定义的全部宏在返回后对导入方可见，包括传递依赖的宏。没有单独的 `export` 标记。`#undef` 也作用于这个共享字典。

循环依赖不会重新处理文件，因此只能观察到进入循环前已经定义的宏，后面的定义不会提前可见。一个模块用不同宏配置多次导入，采用第一次导入的配置。当前是共享预处理环境和单次编译语义，没有独立模块产物或跨构建模块缓存。

同名、同参数名、同替换 token 序列的重复定义允许；空白差异忽略。不同定义是编译错误，并提供此前定义位置。普通字符串和注释内部不会展开宏。宏替换会保留 token 边界，避免 `+`、`+` 意外合成 `++`；支持对象宏、函数宏、嵌套调用和对象宏到函数宏的别名。

条件支持 `#if/#ifdef/#ifndef/#elif/#else/#endif`、`defined`、整数算术、位操作、比较和逻辑短路；未定义标识符按零处理。整数字面量遵循 VAS 的十进制和 `0x/0b/0o/0d` 前缀，支持数字分隔符。支持 `#define`、`#undef`、反斜杠续行和 `#error`；宿主的 `DefineWord` 作为值为 1 的宏参与判断。

当前不支持宏字符串化 `#`、token 拼接 `##` 和可变参数宏；这些写法会报错。宏展开中的字符串需用 `\n` 表达换行，带物理换行的宏字符串会明确被拒绝。普通源码的多行字符串保持原有支持。这是 VAS 的宏子集，不宣称完整 ISO C 预处理兼容。

展开深度最多 64，依赖和条件嵌套最多 128；每节预处理 token 和一次构建的展开工作量分别限制为 100 万，预处理后的单节最大 64 MiB。错误诊断会映射回原文件及 UTF-8 字节列；宏生成的格式串同样进入 `print/println` 编译期格式检查。JSONL 加载报告仍记录实际读取的原始文件字节和依赖事件。

## 性能验证

新增测试入口：

```powershell
ctest --preset windows-msvc-v145-cxx23-release --output-on-failure
# 单独测量：在 out/build/windows-msvc-v145-cxx23 中运行
.\Release\vas_module_performance_test.exe module-performance
```

Windows MSVC v145 Release 微基准采用一次预热、三次测量的中位数，双方都在 OS 文件缓存已预热的条件下测量。加载/预处理和引擎编译分别计时，以下是本机的一次结果：

| 场景 | 原有 builder / 初版实现 | 优化后 | 验证 |
| --- | --- | --- | --- |
| 2,000 个普通函数，加载/预处理 | 原有 0.969 ms | 1.011 ms | 无宏/依赖文件走快速路径，不新增词法扫描 |
| 10,000 次重复引号 include | 原有 19.031 ms | 9.155 ms | 入口和依赖各读一次，共 2 次 |
| 10,000 次混合 import/引号/尖括号 | 不适用 | 9.170 ms | 三种写法合并去重，共 2 次读取 |
| 10,000 次函数宏调用 | 初版 26.911 ms | 16.516 ms | 替换结果为 30,000，与显式展开一致 |

优化包括缓存规范路径及解析结果、哈希去重、读取前预留文件缓冲、借用原始 token 文本、预计算宏参数替换槽、减少临时容器和合并源码映射片段。普通无宏源码保留快速路径；本轮普通文件约增加 0.042 ms，未观察到有意义的编译时间差异，不宣称所有输入都更快。

宏仍有编译前处理成本：同一基准的显式展开源码加载约 3.778 ms，函数宏约 16.516 ms；其后引擎编译分别约 89.7/92.0 ms。不会把预处理成本描述为零。另一项断言比较含变量的函数宏和手写表达式生成的完整函数字节码，要求逐字相同，验证该例没有新增运行时指令。

时间取决于机器、输入和系统负载，不设容易波动的毫秒 CI 门槛。运行输出、重复文件读取次数、重新构建缓存失效、宏字节码一致性以及错误拒绝是硬断言。日志保存在本地 `out/verification/modules/`，未作为通用性能保证。

## 编辑器支持边界

Rider 新包识别模块导入和尖括号依赖，保留原函数 import 的词法结构；词法、依赖和符号扫描有单元测试。当前宏和条件编译下的静态依赖分析仍采取保守策略；配置的搜索根或宏环境无法证明时，不承诺完整重命名和导航。实际编译及宏诊断以原生工具为准。插件安装后需要重启 Rider；原生部署工具更新即可运行这些示例。

完整可运行代码见 [examples/modules](../examples/modules/README.md)。
