# 模块索引、补全与语义颜色

本次交付 Rider 0.5.9、VS Code 0.3.0、VS2026 0.3.0。模块索引保持独立源码模型，另提供即时结构诊断和可配置的后台编译诊断。

三端识别 `import Arena.Demo;`、`#include "Arena/Demo.vas"` 和角括号 include；支持跨文件声明导航、简单类型对象的成员与命名空间补全，并显示所有找到的宏定义候选。枚举值同时支持其命名空间导出及枚举类型限定导航。原有 `import int Fn(...) from "module";` 是函数声明，不被当成文件模块加载。

Rider 还将声明和宏名称接入 Go to Symbol / Search Everywhere，提供类型/函数/变量声明/宏语义颜色。VS Code 提供定义跳转、悬浮、文档符号与语义 token；VS 的 MEF 提供器接入真实原生补全窗口、F12、异步悬浮和类型/函数/宏颜色。VS 与 VS Code 共用词法语法资产，包括 import 模块名、宏定义和格式串占位符颜色。

## 输入、参数提示与错误标记

三端支持 `{}`、`()`、`[]`、双引号和单引号配对，右符号跳过、空符号对退格及块内换行缩进。注释、字符串内不会新增括号对。Rider 的数字分隔单引号不会变成空字符串。函数补全插入 `()` 并将光标放到需要参数的位置；已有左括号时不重复插入。输入 `(`、`,` 可显示参数提示；Rider 用 Ctrl+P、VS Code 用 Ctrl+Shift+Space、VS 用 Edit.ParameterInfo 手动调用。

未闭合括号、字符串/注释及非法字符通过编辑器诊断标红，不要求配置编译器。包含条件预处理分支时，结构检查不猜测活动分支，括号检查交给编译器。

后台编译器读取未保存的当前文件和模块依赖，在临时目录内编译；不保存或改写用户源码。再次编辑后，旧快照结果不会发布。此功能检查当前文件作为入口，并显示属于当前文件的错误；模块需要从依赖它的入口获取完整宿主/宏上下文，不等于完整工程的未保存语义服务。

- Rider：已信任项目，设置应用级 Compiler executable（或既有项目 builder），并提供匹配宿主 API 配置。此次修复应用级已配置而项目 builder 为空时后台诊断不启动的问题，依赖收集支持 import/角括号 include。
- VS Code：已信任工作区，User/Remote 设置 `vas.compilerPath`，`vas.configFile` 指向宿主配置；`vas.liveDiagnostics` 默认 true，450 ms 防抖，可关闭。
- VS2026：Tools → Options → VerseAngelScript → Toolchain 配置 Compiler executable，并启用 Live diagnostics（默认 false，用户明确开启）；项目祖先目录需有 `.vas/vasbuild.config.txt`。源码模型 75 ms 防抖，编译再延迟 400 ms，全局串行检查。

后台检查有依赖数量/源码大小上限和进程超时；VS Code 每个文档最多一个检查进程，VS 全局最多一个，编辑后取消旧进程。自动检查不触发 Build Project。

## 项目文件与生效方式

Rider/NMake 的源码须属于解决方案项目项。部署示例已把 `src/Arena/*.vas`、`basics.vas` 与宏文件列入 `out/deployment/VASDemo/VASDemo.vcxproj`。新增模块用 Add Existing Item，或更新 `<None Include="..." />` 后重新加载项目；仅复制到目录不能保证 Rider 后端将它纳入工程索引。

安装当前源码打包的扩展并重启对应 IDE。旧包不含本次提供器，即使原生编译器已更新，也不会自动获得新语言服务。可用安装包集中复制到 `out/deployment/IDEExtensions/`。

## Rider 查找用法（0.5.9）

Find Usages / Show Usages 的原生入口接入 VAS 只读搜索，使用平台单词索引筛选候选，再按 import/include 闭包、作用域、接收者和参数数确认唯一源码声明。包含宏/条件指令的已知调用不再因重命名覆盖检查而消失。Code Vision 用法计数及 VAS Callers/Callees 同步采用此查询。声明位置与调用位置都能发起原生查找；符号识别复用随 PSI 更新的声明快照，避免用法计数逐次重扫文件全文。真实 Solution Host 验证 `Arena/Demo.vas` 的 `RunBatch` 返回 `main.vas` 中的一个调用，并验证重载歧义不会成为误报。

此结果是源码中的候选用法，可能位于条件宏的非活动分支；尚不表示编译器选定的活动分支。重命名仍使用完整依赖覆盖预检，缺少预处理上下文或绑定歧义时拒绝修改；只读查找不会降低这个约束。

## 模型边界与缓存

编辑器使用源码声明模型，不等于完整编译器类型绑定。条件宏激活、`#undef`、宏展开生成声明、复杂表达式返回类型、继承成员与重载类型选择尚未建模；编辑器显示已找到的声明/宏候选，可能包含非活动分支。歧义导航保留多个候选或不跳转，不随意选同名文件。Rider 重命名仍使用完整覆盖预检，未将部分闭包候选用于重命名。VS Code/VS 没有跨文件重命名。

目录搜索使用局部路径、项目祖先/entry 根提示和 `VAS_INCLUDE_PATH`，不遍历整个磁盘。编辑提示不会代替编译器的 project descriptor 或实际 loaded-source 闭包。VS Code/VS 最多扫描 256 文件、4 MiB/文件、16 MiB 总源码；Rider 的依赖闭包限 256 文件、16 MiB 总源码。未实现的语义以编译结果为准。

VS Code 优先读取打开文档，包括未保存模块，编辑与文件通知使缓存失效。VS 后台读取已登记的打开缓冲区，用快照版本阻止旧结果发布，75 ms 合并连续编辑；磁盘外部改动在下一次补全/悬浮/F12请求重新扫描，纯着色期间不承诺实时检测外部文件。Rider 缓存依赖闭包与 PSI 候选，并复用每次 token 扫描的括号/作用域拓扑。

## 性能评估

下面只计声明扫描或依赖模型，排除 IDE 启动、界面渲染和完整编译。OS 文件缓存可能已预热。

| 测量 | 结果 |
| --- | --- |
| Rider，9 文件竞技场声明扫描，中位数 | 7.47 → 6.95 ms |
| Rider，1500 函数 / 4501 声明，中位数 | 413.12 → 16.10 ms，约 25.7 倍 |
| VS Code，9 文件无模型缓存，31 次中位数 / P95 | 4.84 / 7.36 ms |
| VS Code，复用缓存，中位数 / P95 | 0.98 / 1.34 ms |
| VS Code，main 文件语义查询，中位数 | 0.24 ms |
| VS，重新读取/解析 9 文件，31 次中位数 / P95 | 4.19 / 4.96 ms |
| VS Code，3857 字符文件的即时结构检查，101 次中位数 / P95 | 0.25 / 0.55 ms |
| VS Code，同一文件的输入上下文检查，中位数 / P95 | 0.19 / 0.30 ms |

Rider 优化去掉了逐声明重复构造整个文件的作用域表及扫描前缀，复用单次扫描的括号配对、所在作用域、函数声明判定。优化对比时前后竞技场均保留 162 个声明，合成文件均保留 4501 个声明；之后补齐枚举值新增 3 个声明，不属于性能优化导致的变化；行为回归另行验证。计时是信息性评估，不用易抖动的毫秒阈值替代正确性测试。

复现入口：Rider `VasIndexPerformanceTest`（`vas.performance.phase` 控制证据文件后缀）、`node tools/vscode-extension/test/measureLanguage.js`、VS 核心测试程序 `--language`。
